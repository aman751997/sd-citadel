## The question behind the question

"Design an LLM gateway / AI agent platform" (Anthropic, Datadog, Salesforce ask it) is really: *50 teams are calling 5 model providers with no control — impose order.* It's the API gateway lesson re-armed with AI-specific concerns: cost, fallbacks, safety, and agents that call tools. Your day job (LLM integration in a multi-tenant product) IS this question — treat this lesson as arming an existing war story.

Walk the concerns in this order:

- **One SDK, provider-agnostic schema.** Teams call `/v1/chat`; the gateway translates per provider. Provider lock-in and API drift become the gateway's problem — that's the product pitch in one line.
- **Token-budget limiting per team** (inference lesson: tokens/min buckets + concurrent-stream caps). Budgets are *cost controls*, so they also need monthly ceilings + alerts at 80% — rate limiting meets FinOps.
- **Routing + fallback:** requests declare a capability tier, not a vendor ("fast-cheap" vs "best-quality"); the gateway maps tiers to models. Provider 429/outage → **fallback chain** (Claude → GPT → self-hosted), with a circuit breaker per provider (load-balancing lesson). Streaming makes mid-stream failover mostly impossible — retry-from-start with idempotent logging is the honest answer, say it.
- **The usage ledger** — every call appends `{team, model, tokens_in/out, cost, latency, feature-tag}`, aggregated into dashboards (time-series pattern). "Which team burned $40K last week and on what" is the first question the platform must answer.
- **Cross-cutting safety hooks**: PII redaction pre-send (your vault-pattern war story plugs in here), response moderation, prompt-injection screening for tool-using agents.

## The agent half — tools, loops, and blast radius

An **agent** = LLM in a loop: model proposes a tool call → platform executes it → result goes back into context → repeat until done.

The platform's job is making that loop safe and observable:

- **Tool registry**: typed schemas (name, params, auth scope), per-team allowlists. The model *proposes*; the **platform executes** — the model never holds credentials. That sentence is the security architecture in miniature.
- **Guardrails on the loop**: max iterations, per-step timeout, total token/cost budget per task; a runaway agent stops itself against a wall, not against your bill.
- **Approval gates**: destructive tools (send email, mutate prod data) require human confirm or run dry-run-first. Blast radius is a config property of the tool, not a hope about the model.
- **Tracing (OTEL)**: one trace per task, one span per LLM call/tool call, carrying token counts and cost. Debugging "the agent did something weird at step 7" without a trace is archaeology; with it, it's reading. Distributed-tracing bank question = this section.
- **State**: agent tasks are long-lived → they're jobs (async-jobs template: persisted task row, status, resumability), not requests.
