## When this pattern fires

The input is a linked list (or an array secretly behaving like one — Find the Duplicate), and the ask involves **cycles, middles, ends, reversals, or splicing**. Arrays index; lists *point* — so every technique here is about moving pointers cleverly instead of counting.

**Two tools you'll use in almost every problem:**
- **Dummy head**: `ListNode dummy = new ListNode(0); dummy.next = head;` — makes "delete the head" and "insert before head" stop being special cases. When in doubt, dummy.
- **Draw it.** Four boxes and arrows on paper before coding. Pointer bugs are invisible in code and obvious in a picture — this is your decomposition-under-pressure rep in miniature.

## Form 1 — Fast & Slow (Tortoise & Hare)

Two pointers, one moving 2×. Three distinct super-powers:

**Middle** — when fast hits the end, slow is at the middle:
```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
// even length: slow = SECOND middle. Need first? start fast = head.next.
```

**Cycle detection** — in a cycle, fast laps slow; they must meet:
```java
while (fast != null && fast.next != null) {
    slow = slow.next; fast = fast.next.next;
    if (slow == fast) return true;      // compare NODES (==), never values
}
return false;
```

**Nth from end** (one pass): lead pointer goes n steps ahead, then both walk; when lead hits the end, trail is at target. With a dummy start for trail, trail lands *before* the node to delete — exactly where surgery needs you.

**Find the Duplicate Number** — the transfer test: array values in 1..n treated as pointers (`i → nums[i]`) form a linked structure; a duplicate value = two arrows into one node = **a cycle**. Phase 1 find the meeting point, phase 2 reset one pointer to start, walk both at 1×, they meet at the cycle entrance (Floyd's). Recognizing "array as hidden linked list" cold is a Recognition Fear win waiting to happen.

## Form 2 — In-Place Reversal (the three-pointer dance)

```java
// Reverse Linked List — THE fundamental. Muscle memory required.
public ListNode reverse(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;   // 1. save the rope before cutting it
        cur.next = prev;            // 2. flip the arrow
        prev = cur;                 // 3. advance prev
        cur = next;                 // 4. advance cur
    }
    return prev;                    // prev is the new head (cur is null!)
}
```

The four lines in that exact order. Line 1 before line 2 — cut the rope after grabbing the other side. Return `prev`, not `cur` (cur walked off the end).

**Reverse Linked List II** (section m..n): dummy head → walk to the node *before* m → reverse n−m+1 nodes → **reconnect both seams** (section's old head now points to the node after n; the before-node points to the section's new head). The seams are where all the bugs live — draw them.

**Reverse Nodes in k-Group** (Hard): count k ahead (don't reverse a short tail), reverse the group, recurse or iterate with the seam bookkeeping from II. It's II in a loop — nothing new, just discipline.

## Form 3 — Composite & Structural

**Reorder List** (L0→Ln→L1→Ln-1…) — the pattern showcase, three techniques chained: find middle (fast/slow) → reverse second half → **weave** the two halves. If you can narrate this cold, you own the pattern.

**Merge Two Sorted Lists** — dummy head + tail pointer, splice the smaller node each step, attach the leftover list at the end (no leftover loop needed — it's already linked!).

**Copy List with Random Pointer** — two answers: hashmap `old → clone` (two passes, O(n) space, say it first) or the interleave trick (clone woven between originals: `A→A'→B→B'`, random of clone = `orig.random.next`, then unweave — O(1) space, senior flex).

**LRU Cache** — the structural boss: HashMap for O(1) lookup + doubly-linked list for O(1) recency ordering (move-to-front, evict-from-tail). Every operation: update map AND list together. In Java, mention `LinkedHashMap` exists — then build it manually anyway, because that's the actual test.

## Bug bestiary (pre-loaded)

- **Losing the rope**: writing `cur.next = prev` before saving `next` — rest of the list is gone.
- **Returning `cur`** (null) instead of `prev` from a reversal.
- **`fast.next.next` NPE** — the guard is `fast != null && fast.next != null`, in that order.
- **Seam amnesia** in section reversals — reversed chunk floats disconnected; always reconnect both ends.
- **Comparing values not nodes** in cycle detection — duplicate values false-positive.
- **LRU: map updated, list not** (or vice versa) — the two structures drift; every op touches both.
