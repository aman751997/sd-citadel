## When this pattern fires

Two distinct triggers, two sub-patterns:

1. **Nesting / matching / undo** — brackets, expressions, "most recent open thing must close first". Last-in-first-out is literally the problem statement.
2. **"Next greater/smaller element"** — for each element, find the nearest one to its right (or left) that beats it. The disguises: next warmer day, cars catching up, histogram rectangles, stock spans. This is the **monotonic stack**, and it's the sub-pattern interviews actually test.

Java note: use `ArrayDeque` as your stack (`push/pop/peek`), not the legacy `Stack` class — say it, it's free polish.

## Form 1 — Standard Stack

**Valid Parentheses** — the hello-world: push opens; on a close, the top must be its partner.

```java
public boolean isValid(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        switch (c) {
            case '(' -> st.push(')');
            case '[' -> st.push(']');
            case '{' -> st.push('}');
            default -> { if (st.isEmpty() || st.pop() != c) return false; }
        }
    }
    return st.isEmpty();          // leftovers = unclosed opens
}
```

(Pushing the *expected closer* makes the check one comparison — a small trick worth stealing.) Two classic misses: closing on an **empty stack** (`")("`), and **non-empty stack at the end** (`"(("`). Both in the quiz.

**Min Stack** — O(1) minimum: a second stack tracking the min *as of each level* (push `min(x, curMin)` alongside; pop both together). The general lesson: **augment the stack with per-level metadata** instead of recomputing.

**Evaluate RPN** — numbers push; operators pop two, compute, push. One trap: operand order — `b op a` where `a` popped first (`5 3 -` = 5−3: the SECOND pop is the left operand).

## Form 2 — Monotonic Stack (the real content)

**The reframe that makes it click:** elements sit on the stack because they're **still waiting for their answer**. When a new element arrives, it *answers* everyone on the stack it beats — pop them, record their answers — then waits itself.

```java
// Daily Temperatures — for each day, days until a warmer one
public int[] dailyTemperatures(int[] T) {
    int[] ans = new int[T.length];
    Deque<Integer> waiting = new ArrayDeque<>();      // indexes, temps DECREASING top-down... 
    for (int today = 0; today < T.length; today++) {  // (bottom-up increasing? no: stack holds strictly decreasing temps)
        while (!waiting.isEmpty() && T[today] > T[waiting.peek()]) {
            int answered = waiting.pop();              // today answers this day
            ans[answered] = today - answered;
        }
        waiting.push(today);                           // today now waits
    }
    return ans;                                        // never-answered days stay 0
}
```

**Why O(n) despite the nested while:** every element is pushed once and popped at most once — the while's total work across the whole run is n pops. Say this; the "isn't that O(n²)?" probe is standard.

Which monotonic direction? **Next greater → stack holds decreasing values** (an increasing arrival breaks the order = answers people). Next smaller → increasing stack. Derive it from "who gets answered", don't memorize.

**Next Greater Element II** (circular): loop `2n` times with `i % n`; second lap only answers, never pushes (or push guarded by `i < n`).

**Car Fleet** — monotonic *thinking* without an explicit stack: sort cars by position (closest to target first), compute each car's solo arrival time; sweep — a car catching a slower fleet ahead merges into it (its time gets clamped). Count the distinct times that survive = fleets. The "merge into the thing ahead of you" logic is stack logic in disguise.

**Largest Rectangle in Histogram** — the boss. For each bar: the widest rectangle with THIS bar's height extends until the first *shorter* bar on each side — a next-smaller-element question, both directions at once. Increasing-height stack; when a shorter bar arrives, pop and finalize each taller bar: `height[popped] × (i − stack.peekAfterPop − 1)`. Two implementation saves: **sentinel 0-height bar appended** (flushes the stack at the end) and width when stack empties = `i` (the popped bar saw nothing shorter to its left). This problem is a Hard because of these seams, not the idea — walk it slowly with the buddy before attempting solo.

| "undo", "most recent first", expression eval | standard stack |
| "next greater/warmer/higher …" | monotonic decreasing stack, pop = answered |
| "next smaller" / "first shorter" | monotonic increasing stack |
| circular array variant | 2n sweep with i % n |
| "max rectangle/area under heights" | histogram: next-smaller both sides |
| "X catches up to / merges with Y ahead" | fleet-style sweep (stack thinking) |

## Bug bestiary (pre-loaded)

- **Pop on empty** — `")("`; always `isEmpty()` before pop/peek.
- **Forgetting the end-check** — `"(("` returns true if you only check during the loop.
- **RPN operand order** — second pop is the left operand.
- **Storing values when you need indexes** — Daily Temperatures needs distances; push indexes, compare via `T[idx]`.
- **Histogram: no sentinel flush** — bars still on the stack at the end were never finalized; the answer silently excludes suffix rectangles.
- **`>=` vs `>` in the pop condition** — equal elements: decide who answers whom, be consistent (usually strict `>` for next-strictly-greater).
